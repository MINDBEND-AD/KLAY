# KLAY — MVP implementation plan

Source of truth: `docs/spec.md` v0.4. Milestones per spec §13. Verification legend:
**UT** unit test (Catch2) · **GT** golden-file / null test via `tools/render-cli` · **PV** pluginval strictness 8 +
Steinberg VST3 validator · **RT** real-time-safety harness · **BM** benchmark harness · **PO** manual check by the
product owner (steps written to `docs/checks/Mx.md`).

Every task also needs: build passes, all existing tests still pass, committed with requirement IDs in the message.

## 0. Decisions before M0 (PO answers, 2026-10-19)

Q1–Q18 were answered on 2026-10-19; "Qn" elsewhere in this plan means decision n below. These decisions go into the spec's decision log; the items marked
**spec change** are now in spec v0.4 (see "Spec changes" below).

**Toolchain & project setup**
1. **RT safety check (NFR-001):** MSVC-compatible RT harness in test builds: global `operator new`/`delete` hook plus
   a lock-detection wrapper, armed by a thread-local "audio thread" flag; tests fail on any allocation or lock inside
   `processBlock`. A clang-cl + RTSan job can follow later.
2. **Hosts:** M0 and the M5 smoke test use Ableton Live, Reaper and FL Studio. The other FR-007 hosts (Bitwig, Cubase,
   Studio One) stay untested until the PO has access.
3. **CI:** M0 sets up a public GitHub repo (AGPLv3) with GitHub Actions. Prerequisites the PO does once: install Git
   for Windows and GitHub CLI, set git `user.name`/`user.email`, and run `gh auth login`. Creating the repo still asks
   for the PO's go-ahead at that step.
4. **Plugin identity (fixed from M0, never changed):** manufacturer "MINDBEND AD", manufacturer code `KLAY`, bundle ID
   `com.01.klay`, name in hosts "Klaymore" (bundle `Klaymore.vst3`). Plugin code `klay` (confirmed 2026-10-19; it has
   no capital letter, which is fine for VST3 but would need to change for an AU build). The project and repo keep the working title KLAY. User data:
   `%APPDATA%\MINDBEND AD\Klaymore\`.

**Content**
5. **Factory samples:** the dev build reads the library from a configurable path; automated tests use synthetic kicks
   generated by the test suite. Delivery date and location are still open; they are needed before task 1.17 (LT-1)
   and task 2.1.

**Behaviour the spec didn't define**
6. **Key Track:** no global switch. Active for every layer with P (pitch-follow) on; the note equal to the detected
   root plays untransposed. With no detected key, follow layers play untransposed and the key display shows "—".
7. **Autogain (FR-109):** Autogain on/off switch in Settings, default On. One gain from the summed pre-FX buses
   (Main + A1 + A2), applied equally to all buses. **Spec change** (UI-017).
8. **Ranges (spec change):**
   - Layer fader: −∞ to 0 dB, default 0 dB. Travel weighted to the top end: the upper range (about −12 to 0 dB) gets
     most of the fader travel; low values are packed towards the bottom.
   - Pitch knob: ±12 semitones and ±100 cents.
   - Stretch knob: 0.25–8×, logarithmic travel, default 1× (an exception to UI-019's "linear except Mono").
   - End-of-kick soft fade (FR-108): 5 ms.
   - Mono slope default: 12 dB/oct. The Settings wireframe (shows 24) needs updating.
9. **Trim (FR-102):** start and end trim, each as a handle on the left and right edge of the selected layer's waveform
   in Layer view. **Spec change:** FR-102 adds end trim; FR-103 no longer says the envelope replaces end trim. The
   envelope still replaces fades.
10. **Envelope curves (FR-281):** per-segment power curve, tension −1…+1.
11. **Sum view and Clip:** a display-only background render through all chains, Mono, master fader and TP at the Live
    factor after each edit; the pre-FX sum until M4.
12. **Finalizer neutral state:** with Clip gain 0 dB and the block's peak below the ceiling, the clipper path is
    bypassed with latency kept (bit-identical); otherwise "untouched" means a null better than −90 dB.
13. **Host automation (FR-006):** the MVP exposes master gain, aux return levels, aux mutes, Mono and TP only. FX module
    automation moves to M6. Parameter IDs are frozen from M4 on (FR-235).
14. **Dev editor:** a temporary dev editor in M1–M2 (load kick JSON, per-layer controls, audition; in M2 also
    Randomize All, roll, lock, undo). It is removed in M3; UC-1/UC-2 are re-checked on the real UI.
15. **Module presets:** each module ships only "Init" in the MVP; Distortion per-mode presets follow when the PO
    delivers the names.
16. **Export:** 24-bit with deterministic TPDF dither (fixed seed, keeps NFR-009); 32-bit float without dither.
    **Open for review before the MVP release (M5): dither yes or no?** This default stays until then.

**Spec cleanup**
17. Drop the stale decision log row "Roll template default: Punch + Crunch + Transient" and "usually carries the key"
    from the Crunch glossary entry. The "Input on Distortion only" row is already superseded by FR-229.
18. Catch2 v3; dependencies pinned via FetchContent (JUCE 8.x, Signalsmith Stretch, Catch2, VST3 SDK for its
    validator); pluginval at a pinned release. Samples are resampled to the session rate on load. Changing the
    oversampling factor reports the new latency to the host. A roll avoids re-drawing the layer's current sample when
    the pool has more than one.

**M1 notes and deviations (Claude Code, 2026-10-19)**
- 1.1: JSON via nlohmann/json v3.12.0 (MIT, new row in THIRD_PARTY_LICENSES.md); the M0 `StateHeader` stub is
  replaced by `model::Kick` (stack + settings). Fader −∞ is stored as −144 dB (JSON has no infinity).
- 1.2–1.6 were built and committed together (one commit naming each task), since they share the CMake wiring and
  test files.
- 1.2: loader resamples with JUCE `WindowedSincInterpolator` (load-time quality); files over 30 s are rejected.
- 1.4: envelope tension uses p = 8^|tension|, t^p for positive and 1 − (1 − t)^p for negative tension (both
  power curves), so a segment is never steeper than 8× its straight line and cannot click (FR-285). A segment takes
  the tension of its start point.
- 1.5: Repitch primes the JUCE interpolator with its base latency at ratio 1, so Repitch adds no delay (UT).
- 1.6 (**deviation, PO to review with LT-1/LT-2**): Signalsmith Stretch 1.4.0 meets "exact length" and "sine pitch
  ±2 cents" for pure length changes over 0.25–8× (default preset; cheaper up to 2×), and "level ±1 dB" up to 4×
  (default) / below 2× (cheaper); at 8× it loses up to ~3.5 dB on a sine. Its length-preserving **pitch shift** misses
  a pure sine by up to ~8 cents (default preset, 330 Hz, −12…+12 st) and ~20 cents (cheaper). Tests bound the
  measured values (±10 cents, ±4.5 dB) to catch regressions. If Key Track needs exact tuning, an option is pitch
  via Signalsmith time-stretch by the ratio plus a Repitch by the same ratio (exact pitch, different artefacts).
  Stretch uses a fixed random seed for NFR-009. Signalsmith Linear 0.6.4 (MIT) is pinned and listed as its own row.
- 1.7: Repitch mode (spec FR-106 as updated 2026-10-19): the Pitch knob is ignored and the Stretch knob is the
  varispeed (length × s, pitch −12·log2(s) st, JUCE Lagrange); UT added. Envelope time
  is the kick timeline (offset included). Layers are processed in parallel (std::async) and processed parts are
  cached by everything that affects them, so fader/offset/envelope/mute/solo/routing edits skip Signalsmith.
  Mute/solo click rules (`model::clickMute`, `clickSolo`) were needed for the 1.7 test and are in place for 2.4.
- 1.8: `core/render/RenderEngine` (std::thread worker, JUCE-free) hands renders to the audio thread through an
  atomic pointer guarded by hazard-pointer slots (`core/rt/HazardSlots.h`); the worker frees replaced renders.
  BM (dev machine, Release): re-render after a fader edit, 12 layers, 1 beat at 150 BPM: ~2 ms (target < 30 ms).
- 1.9: `core/render/KickPlayer` (JUCE-free) holds two voices (ringing + new) in hazard slots of the render engine.
  The processor splits each block at note-on positions (sample-accurate), ignores velocity and note-offs, and sums
  Main + A1 + A2 to the output (no FX chains until M4). Audition API: `KlayProcessor::triggerAudition()`.
- 1.10: the audio thread stores the playhead BPM in an atomic; a 20 Hz message-thread timer feeds
  `render::TempoDebouncer` (150 ms settle, 0.005 BPM tolerance) and re-renders unless the manual override is on.
- 1.11: YIN uses threshold 0.15, frames from the energy peak until −30 dB, settled tail = voiced frames after the
  first 40 %; uncertain when YIN and the FFT peak differ by more than 50 cents. Results are memoised per processed
  key-layer part (YIN alone took ~80 ms per render).
- 1.13: the processor state is the full `model::Kick` JSON; parts load on the render thread through `SampleCache`
  (session rate in the key); missing parts are listed by `getMissingSamples()` and stay silent.

## M1 second pass (spec v0.9: one layer knob, Length / Pitch / Tape)

M1 was built and accepted on spec v0.4 (two knobs, Pitch + Stretch, plus a Stretch/Repitch mode). Spec v0.6–v0.9
replace that with one layer knob and a three-way mode switch (FR-104–106, UI-007, UI-019; decision log rows v0.6 and

**Questions, answered by the PO on 2026-10-19 (all proposals accepted)**
- **Q-A Tape value:** UI-007 labels the Tape knob "Speed 0.25–8×", FR-106 says "0.25–8×". Decision: the stored value is
  the speed (2× = one octave up and half the length), the readout shows the resulting pitch (−24…+36 st). The current
  M1 code instead treats the Stretch knob as a length factor in Repitch mode (2× = twice as long, one octave down).
  The Kick page mock does the same as the M1 code (see C1).
- **Q-B Migration of v1 kicks:** a v1 layer in Stretch mode could have both a length change and a pitch change; v2
  applies only one. Decision: keep both values in their modes (nothing is lost) and make Length active if its factor
  is not 1×, else Pitch if the pitch is not 0, else Length; a v1 Repitch layer becomes Tape with speed = 1 / old
  stretch. Such a kick then sounds different from v1 (only one transform applied); the loader reports it once.
- **Q-C Undo:** FR-106 makes a mode switch one undo step; the undo manager arrives in M2 (2.5), which will cover it.
- **Q-D Key Track and Tape:** Tape changes the pitch of a pitch-following layer before Key Track; key detection on the
  key layer uses its processed (active-mode) sample, as now. Decision: this order.

- 2.1: `core/library/SampleIndex` scans `<root>/<Role>/<sub-folders…>/<file>` (role folders matched case-insensitively,
